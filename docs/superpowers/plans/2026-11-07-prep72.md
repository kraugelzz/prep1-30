# พร้อม 72 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** สร้าง PWA ออฟไลน์ "พร้อม 72" ตามสเปก `docs/superpowers/specs/2026-11-07-prep72-design.md`

**Architecture:** HTML/CSS/JS ล้วนแบบ ES modules ไม่มี build step ตรรกะ (progress, scam, store) เป็นฟังก์ชันบริสุทธิ์ที่ทดสอบด้วย `node --test`; `app.js` เป็นตัว render ตาม hash route; `sw.js` cache-first ทุกไฟล์

**Tech Stack:** ES2022 modules, Node 24 `node:test`, Service Worker, Web App Manifest, IBM Plex Sans Thai (OFL)

## Global Constraints

- ห้ามโหลดทรัพยากรจากนอก origin (สคริปต์ ฟอนต์ รูป)
- ห้ามมีช่องกรอกรหัสผ่าน เลขบัญชี เลขบัตร เลขบัตรประชาชน

- ฟอนต์ IBM Plex Sans Thai 400/500 เท่านั้น; % 56px, หัวข้อ 24px, เนื้อหา 16px, รอง 13px, line-height ≥ 1.6
- localStorage key `prep72.v1`, schema `version: 1`
- ถามผู้ใช้ก่อนสร้าง repo GitHub และก่อน push

### Task 2: ความคืบหน้า (`js/progress.js`)

**Interfaces — Consumes:** `ITEMS`, `ORDER` · **Produces:**
- `percent(state, items) → number` (จำนวนเต็ม 0–100, นับ `state.done`)
- `groupPercent(state, items, group) → number`
- `expiringIds(state, today:Date, days=30) → string[]` (done + expiry ≤ today+days)
- `nextItem(state, order, today:Date) → {id:string, reason:'expiring'|'todo'|'skipped'} | null`
  ลำดับ: expiring ก่อน → ข้อแรกใน order ที่ไม่ done และไม่ skipped → ข้อแรกที่ skipped และไม่ done → null

- [ ] tests: state ว่าง → 0% และ next = order[0]; done 15/30 → 50; ข้าม order[0] → next = order[1]; ทุกข้อ done ยกเว้นข้อที่ข้าม → reason 'skipped'; done ครบ → null; done ครบแต่ kit-1 หมดอายุใน 10 วัน → {id:'kit-1', reason:'expiring'}; หมดอายุใน 60 วัน → null
- [ ] implement → PASS, commit

### Task 4: เก็บข้อมูล (`js/store.js`)

**Produces:**
- `defaultState() → {version:1, done:{}, skipped:{}, expiry:{}, dailySpend:null, contacts:[], meetNear:'', meetFar:'', sosChecked:[]}`
- `createStore(storage|null) → {state, persistent:boolean, update(fn), reset(), exportJSON():string, importJSON(text):{ok:true}|{ok:false,error:string}}`
  storage โยน error ได้ทุกเมื่อ → ห่อ try/catch; ถ้าใช้ไม่ได้ persistent=false และเก็บในหน่วยความจำ
  importJSON ตรวจ: parse ได้, version===1, done/skipped/expiry เป็น object, contacts เป็น array — ไม่ผ่านต้องไม่แตะ state เดิม

- [ ] tests ด้วย fake storage (Map) และ storage ที่ throw: บันทึกแล้วโหลดใหม่ได้ค่าเดิม; storage throw → persistent false แต่ update ใช้ได้; import ไฟล์เสีย/ผิดเวอร์ชัน → ok false และ state ไม่เปลี่ยน; export→import ไปกลับได้เท่าเดิม
- [ ] implement → PASS, commit
